# Covariance Estimation Matters for Multidimensional Normative Modeling

Code, summary outputs, and supplementary materials for *Covariance Estimation
Matters for Multidimensional Normative Modeling: A Demonstration with
Obsessive–Compulsive Disorder*.

`MANIFEST.md` maps every table and figure in the manuscript and supplement to the
script and output file that produced it. The supplementary materials themselves
(Supplements S1–S8) are in `docs/supplementary_materials.pdf`.

DOI: https://doi.org/10.5281/zenodo.22878835 (all versions; resolves to the latest)

Licence: the code under `code/` and `data/synthetic/` is MIT (see LICENSE); the written
materials and summary outputs are CC BY 4.0 (see LICENSE-DOCS). The registry data are
covered by neither and are not included.

## What is and is not here

The clinical registry data are **not** included. Participant consent and IRB approval
do not permit public release of individual-level records. They are available from the
corresponding author on reasonable request and under a data use agreement.

What is included: all analysis code, a synthetic dataset built from published aggregates,
and the summary outputs behind every reported table and figure.

The synthetic file is generated by `data/synthetic/make_synthetic_data.py` from group
means, standard deviations, floor prevalences and the latent correlation matrix. No real
record is resampled or perturbed. It reproduces the floor geometry well enough that MCD
collapses onto a floored subset and Ledoit-Wolf does not, which is the paper's central
phenomenon, but it reproduces no reported estimate. Scripts `03`, `06` and `07` accept
`--data data/synthetic/synthetic_clinical_data.csv`; `01` and `02` need the item-level
export and cannot run against it.

Two consequences worth stating plainly.

**Study 1 reproduces, with one documented exception.** `05_study1_simulation.py` reads
no participant data, and at the seeds recorded below it returns the reported values
except where an MCD fit is rank-deficient or nearly so: chiefly the .75-floor
condition, a few .50-floor cells at n = 5,000, and the singular fits in the
support-fraction sweep (`07`). For those fits, whether a near-zero eigenvalue falls
above or below the pseudoinverse cutoff turns on floating-point details of the machine
and linear-algebra library, so values such as the .75-floor MCD median ratio and
singular-fit rate can differ between runs even with the same code, seeds and pinned
package versions. The
manuscript flags these values as unstable, and `check_reproduction.py` tests the
.75-floor singular-fit rate as a range for this reason. Everything in `outputs/` comes
from the run reported in the paper.

**Study 2 does not.** Scripts `01`, `02`, `03`, `06`, and `07` require the registry data.
Run against the synthetic dataset they execute end to end and produce output of the right
shape, which lets you verify the implementation, but the numbers will not match the paper.
The reported Study 2 values are in `outputs/`.

## Layout

```
code/      analysis scripts, numbered in run order
data/      synthetic dataset and its generator; registry files go here if you have them
docs/      supplementary materials (PDF) and an analysis log of post hoc additions
outputs/   summary tables and figures (also where scripts write)
env/       environment pins
```

## Environment

Python 3.11.8 with the packages in `env/requirements.txt`.

With conda, which is the easier route on Windows if you already have Anaconda:

```
conda create -n covest python=3.11.8 -y
conda activate covest
pip install -r env/requirements.txt
```

Or with the standard library:

```
python -m venv .venv && source .venv/bin/activate    # Windows: .venv\Scripts\activate
pip install -r env/requirements.txt
```

Either way, use a dedicated environment rather than conda's `base`. The runners print
the interpreter path at startup so you can confirm which one is active.

**scikit-learn must be 1.8.0.** `MinCovDet` changed across releases, and the change is
not cosmetic: at a fixed seed on these data, version 1.4.2 returns a condition number of
155.71 and a reweighted support of 40, while 1.8.0 returns 172.23 and 38. The manuscript
reports the 1.8.0 values. Nothing outside MCD is affected.

## Running the scripts

Run them from the repository root, as files rather than in an interactive
console. Use `python` on the front: without it Windows resolves `code` as the
VS Code launcher, and conda environments do not include the `py` launcher.

```
python code/01_clean_and_score.py
```

Most scripts take `--base` to point somewhere else. Pasting a script into an IDE
console or notebook also works, but `__file__` does not exist there, so the
scripts fall back to the working directory: start from the repository root or
pass `--base`.

## Run order

Each script takes `--base` (default: the repository root) and writes to `outputs/`.
`04` depends on an output of `03`, and `05` depends on a matrix derived in `04`, so the
order matters.

| # | Script | Reads | Writes |
|---|--------|-------|--------|
| 01 | `01_clean_and_score.py` | `data/final_df.csv` | `data/imputed_clinical_data.csv` |
| 02 | `02_descriptives_octcdq_bfas.py` | `data/final_df.csv` | Table 3 rows, BFAS key diagnostics |
| 02b | `02b_feature_reliability.py` | `data/final_df.csv` | feature and BFAS aspect reliability |
| 03 | `03_phase2_analyses.py` | `data/imputed_clinical_data.csv` | Study 2 tables and figures |
| 04 | `04_invert_r.py` | `outputs/TableS_feature_correlations_hc.csv` | `outputs/latent_R.csv` |
| 05 | `05_study1_simulation.py` | nothing | Study 1 tables and figures |
| 05b | `05b_figure1.py` | `outputs/Study1_runs.csv`, `outputs/Study1_summary.csv` | Figure 1 with across-seed interquartile bands (replaces 05's version) |
| 06 | `06_bootstrap_sample_size.py` | `data/imputed_clinical_data.csv` | Supplement S6 |
| 07 | `07_support_fraction_sweep.py` | `data/imputed_clinical_data.csv` | Supplement S5 |
| 08 | `08_fig_mcd_discarded.py` | `outputs/TableS_mcd_support_composition.csv` | Figure 2 |

Or run everything in order with one command:

```
run_all.bat                 Windows
./run_all.sh                macOS and Linux
run_all.bat synthetic       against the synthetic dataset
```

It activates `.venv` if present, warns if scikit-learn is not 1.8.0, stops at the
first failure, and finishes with both checks. The individual commands are:

```
python code/01_clean_and_score.py
python code/02_descriptives_octcdq_bfas.py
python code/02b_feature_reliability.py
python code/03_phase2_analyses.py
python code/04_invert_r.py
python code/05_study1_simulation.py
python code/05b_figure1.py
python code/06_bootstrap_sample_size.py
python code/07_support_fraction_sweep.py
python code/08_fig_mcd_discarded.py
```

`05`, `06`, and `07` accept `--quick` or `--n-seeds` for a fast check; `05` at full
settings takes the longest.

## One manual step

`04_invert_r.py` writes `outputs/latent_R.csv`, the latent correlation matrix used by the
`floor_matched_corr` condition. That matrix is currently **pasted by hand** into
`05_study1_simulation.py` as the constant `R_MATCHED`. If you re-run `04` on different
data, the constant will no longer match the file and nothing will warn you. Either have
`05` read the CSV, or add an assertion that the two agree to four decimals.

## Seeds

Thirty seeds throughout, but not the same thirty. Study 1 (`05`) uses 1000-1029; the
bootstrap sample-size analysis (`06`) and the support-fraction sweep (`07`) use 42-71.
The Study 2 real-data MCD fit (`03`) uses seed 42. All are set in the scripts; nothing
depends on the system clock.

## Before a clean run

Empty `outputs/` first. Later scripts read what earlier ones write, so a stale file
will let a step succeed after the step it depends on has failed.

## Checking a run

After a full pass over the real data:

```
python code/check_reproduction.py
```

It compares ten reported quantities against what is now in `outputs/` — the
Study 1 calibration and singular-fit rates, the real-sample MCD fit, the partial
correlation and its interval, and the sweep's singular-fit count. Every script can
finish without error and still produce the wrong numbers, so a clean run of the
scripts is not the same as a reproduction. If the MCD rows differ, check the
scikit-learn version first.

## If you re-run these scripts

`03_phase2_analyses.py` writes two participant-level files from whatever data it is
given: `final_analyzed_dataset.csv`, one row per participant, and
`TableS_step3_top_leverage.csv`, five individual high-leverage cases with their sex
category. Neither is published here, and neither should be shared. `.gitignore`
excludes them by name, but an archive built from the folder will pick them up, so
delete them first.

```
python code/check_outputs.py
```

flags anything in `outputs/` carrying an identifier column, a demographic column, or a
row count matching one of the sample sizes. It reads shape rather than meaning, so
treat a clean run as one piece of evidence rather than a clearance.
